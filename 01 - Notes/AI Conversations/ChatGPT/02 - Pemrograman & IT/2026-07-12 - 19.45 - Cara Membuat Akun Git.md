## 📁 Working Directory (Area Kerja)
image_group{"aspect_ratio":"1:1","query":["working directory git concept files edited","coding files being edited in folder example","developer editing code files laptop project"],"num_per_query":1}
**Working directory** adalah:
- Folder project kamu di komputer  
- Tempat kamu **edit, tambah, hapus file**  
- Perubahan di sini **belum tersimpan di Git**

👉 Ibaratnya: tempat kamu *ngetik dan ngedit kerjaan*

**Contoh:**
- Kamu buka `index.html`
- Tambah teks: `"Hello World"`
- Simpan file

➡️ Perubahan ini **hanya ada di working directory**, belum masuk Git

---

## 🗃️ Local Repository (Database Git)
image_group{"aspect_ratio":"1:1","query":["git commit history graph visualization","git repository commits tree example","git log terminal output commits"],"num_per_query":1}
**Local repository** adalah:
- Tempat Git menyimpan **riwayat perubahan (commit)**  
- Ada di folder tersembunyi `.git`  
- Semua yang sudah di-**commit** akan masuk sini

👉 Ibaratnya: tempat penyimpanan versi resmi project kamu

**Contoh:**
```bash
git add index.html
git commit -m "tambah hello world"
```

➡️ Sekarang perubahan tadi **masuk ke local repository**

---

## 🔄 Alur sederhana
image_group{"aspect_ratio":"1:1","query":["git workflow working directory staging repository diagram simple","git add commit flow illustration","git staging area concept diagram"],"num_per_query":1}
1. Edit file → masuk **working directory**  
2. `git add` → masuk **staging area**  
3. `git commit` → masuk **local repository**

---

## 🎯 Perbedaan utama

| Working Directory | Local Repository |
|------------------|----------------|
| Tempat edit file | Tempat simpan commit |
| Belum disimpan Git | Sudah tersimpan permanen |
| Bisa berubah kapan saja | Lebih “resmi” (versi tersimpan) |
| Tidak ada riwayat | Ada history |

---

1. Edit file:

➡️ Masih di **working directory**

2. Tambahkan:
```bash
git add app.txt
```

3. Commit:
```bash
git commit -m "tambah file app"
```
➡️ Sekarang masuk **local repository**

---

- **Working directory = tempat kerja**
- **Local repository = tempat simpan hasil kerja (versi)**

## ⚙️ Apa itu `git config`?
image_group{"aspect_ratio":"1:1","query":["git config terminal example user name email","git configuration global settings illustration","git setup username email command line"],"num_per_query":1}

**`git config`** digunakan untuk:
👉 mengatur **identitas dan pengaturan Git** di komputer kamu  

---

## 🧠 Fungsi utamanya
### 1. 👤 Menentukan identitas
Ini yang PALING penting:

```bash
git config --global user.name "NamaKamu"
git config --global user.email "emailkamu@example.com"
```

➡️ Setiap kamu commit, Git akan mencatat:
- siapa yang buat perubahan  
- email siapa  

Contoh hasil commit:
```
Author: Yohanes <email@example.com>
```

---

### 2. 🌍 Mengatur global vs local

#### 🔹 Global (untuk semua project)
```bash
git config --global user.name "Yohanes"
```

➡️ Berlaku untuk semua repo

---

#### 🔹 Local (hanya project tertentu)
```bash
git config user.name "Yohanes Project1"
```

➡️ Hanya berlaku di folder itu saja

---

### 3. 🔧 Setting lain (opsional)
Contoh:
```bash
git config --global core.editor "code --wait"
```
➡️ Mengatur editor (VS Code)

---

## 🔍 Cara melihat config
```bash
git config --list
```

Atau:
```bash
git config user.name
```

---

## ⚠️ Kenapa ini penting?
Kalau tidak di-set:
- commit bisa gagal ❌  
- atau tidak jelas siapa pembuatnya ❌  

---

## 💡 Analogi sederhana
- `git config` = isi **nama & identitas di KTP**  
- `commit` = tanda tangan kamu di dokumen  

---

## 🔥 Ringkasan
- `git config` → untuk setting Git  
- Paling penting: **user.name & user.email**  
- Bisa global atau per project
