## 1. Git itu apa?

**Git** adalah alat untuk mencatat riwayat perubahan file, terutama kode. Dengan Git, kamu bisa:

- melihat perubahan dari waktu ke waktu
- kembali ke versi lama
- membuat cabang eksperimen tanpa merusak kode utama
- bekerja bersama orang lain lewat GitHub, GitLab, Bitbucket, dan sejenisnya

Bayangkan Git seperti **save point berlapis** untuk proyekmu.

---

## 2. Konsep penting yang wajib ingat

### Repository / repo

Folder proyek yang dipantau Git.

```bash
git init
```

Artinya: jadikan folder ini sebagai repository Git.

---

### Working directory

File yang sedang kamu edit sekarang.

---

### Staging area

Tempat menyiapkan perubahan sebelum disimpan ke riwayat Git.

```bash
git add nama_file
```

Atau semua file:

```bash
git add .
```

---

### Commit

Snapshot perubahan yang disimpan ke riwayat Git.

```bash
git commit -m "Pesan commit"
```

Contoh:

```bash
git commit -m "Tambah halaman login"
```

---

### Branch

Cabang kerja. Biasanya branch utama bernama `main` atau `master`.

Cek branch:

```bash
git branch
```

Buat branch baru:

```bash
git branch fitur-login
```

Pindah branch:

```bash
git switch fitur-login
```

Buat sekaligus pindah:

```bash
git switch -c fitur-login
```

---

### Merge

Menggabungkan perubahan dari satu branch ke branch lain.

Misalnya kamu selesai kerja di `fitur-login`, lalu mau gabungkan ke `main`:

```bash
git switch main
git merge fitur-login
```

---

### Remote

Repo yang ada di server, misalnya GitHub.

Cek remote:

```bash
git remote -v
```

Tambah remote:

```bash
git remote add origin https://github.com/user/nama-repo.git
```

---

### Push

Mengirim commit lokal ke remote.

```bash
git push
```

Pertama kali biasanya:

```bash
git push -u origin main
```

---

### Pull

Mengambil perubahan terbaru dari remote lalu menggabungkannya ke lokal.

```bash
git pull
```

---

### Clone

Mengunduh repository dari remote ke komputer.

```bash
git clone https://github.com/user/nama-repo.git
```

## 7. Undo / membatalkan perubahan

Ini bagian penting.

### Membatalkan perubahan file yang belum di-add

```bash
git restore nama_file
```

Semua file:

```bash
git restore .
```

Hati-hati, ini membuang perubahan lokal.

---

### Mengeluarkan file dari staging

Kalau sudah `git add`, tapi belum commit:

```bash
git restore --staged nama_file
```

---

### Mengubah pesan commit terakhir

```bash
git commit --amend -m "Pesan commit baru"
```

---

### Membatalkan commit terakhir, tapi perubahan tetap ada

```bash
git reset --soft HEAD~1
```

---

### Membatalkan commit terakhir dan perubahan kembali ke working directory

```bash
git reset HEAD~1
```

---

### Membatalkan commit dan membuang perubahannya

```bash
git reset --hard HEAD~1
```

Hati-hati. Ini bisa menghapus perubahan.

## 8. Conflict itu apa?

Conflict terjadi saat Git tidak bisa otomatis menggabungkan perubahan.

Contoh: kamu dan temanmu mengubah baris yang sama di file yang sama.

Biasanya file akan terlihat seperti ini:

```text
<<<<<<< HEAD
kode versi kamu
=======
kode versi branch lain
>>>>>>> fitur-lain
```

Cara menyelesaikan:

1. Buka file yang conflict.
2. Pilih versi yang benar, atau gabungkan manual.
3. Hapus tanda `<<<<<<<`, `=======`, `>>>>>>>`.
4. Jalankan:

```bash
git add .
git commit
```

Kalau conflict terjadi saat pull/merge, Git biasanya memberi tahu file mana yang bermasalah.

## 9. `.gitignore`

File `.gitignore` dipakai untuk memberi tahu Git file/folder mana yang tidak perlu dilacak.

Contoh `.gitignore` untuk proyek Node.js:

```gitignore
node_modules/
.env
dist/
.DS_Store
```

Contoh untuk Python:

```gitignore
__pycache__/
.env
venv/
*.pyc
```

Setelah membuat `.gitignore`:

```bash
git add .gitignore
git commit -m "Tambah gitignore"
```

## 10. Perbedaan `fetch`, `pull`, dan `push`

### `git fetch`

Mengambil informasi terbaru dari remote, tapi belum mengubah branch lokal.

```bash

```

### `git pull`

Mengambil update dan langsung menggabungkannya.

```bash
git pull
```

Kurang lebih sama seperti:

```bash
git fetch
git merge
```

### `git push`

Mengirim commit lokal ke remote.

```bash
git push
```

## 11. Rebase secara sederhana

`rebase` dipakai untuk “memindahkan” commit branch kamu ke atas commit terbaru branch lain.

Contoh:

```bash
git switch fitur-login
git fetch
git rebase origin/main
```

Biasanya dipakai agar riwayat commit lebih rapi.

Untuk pemula, cukup ingat:

- `merge` lebih mudah dan aman
- `rebase` membuat history lebih rapi
- jangan sembarangan rebase branch yang sudah dipakai banyak orang

## Terminal atau Git?

Biasanya alurnya begini:

1. **Tulis/edit kode** di editor, misalnya VS Code.
2. **Jalankan perintah Git** di terminal.
3. **Simpan versi perubahan** dengan `commit`.
4. **Kirim ke GitHub/GitLab** dengan `push`.

Jadi kamu tidak “bekerja di Git”, tapi **bekerja di proyek lokal**, lalu Git mengelola riwayatnya.

## Git vs GitHub

Ini penting:

| Nama | Fungsi |
|---|---|
| **Git** | Program di komputer untuk version control |
| **GitHub** | Website/server untuk menyimpan repo Git online |
| **Terminal** | Tempat mengetik perintah Git |
| **VS Code** | Editor untuk menulis kode, juga bisa menjalankan Git lewat UI |

Git bisa dipakai tanpa GitHub. Tapi kalau mau backup online atau kerja tim, biasanya pakai GitHub.

## Masalah yang terjadi di layar kamu

### 1. Kamu menjalankan `git init` di folder `Documents`

Ini membuat seluruh folder `Documents` menjadi Git repository:

```bash
Initialized empty Git repository in /Users/YS/Documents/.git/
```

Sebaiknya **jangan jadikan seluruh Documents sebagai repo**, karena isinya banyak file pribadi seperti `.pdf`, `.docx`, `.xlsx`.

Nanti kita bersihkan.

---

### 2. `git add satu` gagal

Kamu mengetik:

```bash
git add satu
```

Git bilang:

```bash
fatal: pathspec 'satu' did not match any files
```

Artinya tidak ada file bernama `satu`.

Lalu kamu benar saat mengetik:

```bash
git add ttd.pdf
```

Tapi ini masih di folder `Documents`, bukan di repo GitHub `Latihan-git`.

---

### 3. Kamu mengetik URL langsung

Kamu mengetik:

```bash
https://github.com/Yohanespck/Latihan-git.git
```

Terminal mengira itu perintah, jadi error.

URL GitHub harus dipakai bersama perintah, misalnya:

```bash
git clone https://github.com/Yohanespck/Latihan-git.git
```

---

### 4. `cd Desktop` gagal

Terminal bilang:

```bash
cd: no such file or directory: Desktop
```

Mungkin karena kamu sedang di `Documents`, jadi `Desktop` tidak ada di dalam `Documents`.

Gunakan ini untuk pindah ke Desktop:

```bash
cd ~/Desktop
```

Atau lebih aman, pindah ke home dulu:

```bash
cd ~
```

---

### 5. GitHub menolak password

Error ini penting:

```bash
Password authentication is not supported for Git operations.
```

GitHub sekarang **tidak menerima password akun biasa** untuk operasi Git lewat terminal.

Tapi karena repo kamu terlihat **Public**, seharusnya untuk `git clone` tidak perlu login. Jadi kemungkinan URL atau autentikasi terminal kamu sedang bermasalah.

---

## Langkah perbaikan sekarang

Ikuti pelan-pelan.

### 1. Bersihkan Git yang terlanjur dibuat di Documents

Karena kamu masih berada di folder `documents`, jalankan:

```bash
rm -rf .git
```

Ini hanya menghapus pengaturan Git di folder `Documents`, **bukan menghapus file dokumen kamu**.

Lalu cek:

```bash
ls -a
```

Kalau `.git` sudah tidak terlihat, berarti bersih.

---

### 2. Pindah ke folder yang aman untuk latihan

Jalankan:

```bash
cd ~
mkdir latihan
cd latihan
```

Sekarang kamu berada di folder baru khusus latihan.

---

### 3. Clone repository dari GitHub

Di GitHub, klik tombol hijau **Code**, lalu copy URL dari tab **HTTPS**.

Kemudian di terminal jalankan:

```bash
git clone https://github.com/Yohanespck/Latihan-git.git
```

Pastikan tidak ada tanda kurung, tidak ada `[ ]`, tidak hanya URL saja.

Kalau berhasil, akan muncul folder `Latihan-git`.

Lalu masuk ke folder itu:

```bash
cd Latihan-git
```

Cek isinya:

```bash

```

Seharusnya terlihat:

## Kalau masih diminta username/password

Kalau saat `git clone` masih muncul:

```bash
Username for 'https://github.com':
Password for 'https://...':
```

batalkan dulu dengan tekan:

```text
Control + C
```

Lalu coba clone dengan URL ini:

```bash
git clone https://github.com/Yohanespck/Latihan-git.git
```

Kalau masih tetap minta login, kemungkinan repo tidak benar-benar public atau credential di Mac kamu bermasalah.

Cara paling mudah untuk pemula: gunakan **GitHub Desktop**. Tapi kalau mau tetap terminal, nanti kita bisa pakai **Personal Access Token** atau **GitHub CLI**.

Error ini:

Artinya perintah `code` untuk membuka VS Code belum aktif.

Tidak masalah. Kamu bisa buka VS Code manual:

1. Buka aplikasi **Visual Studio Code**
2. Pilih **File > Open Folder**
3. Pilih folder `Latihan-git`

Nanti kalau mau mengaktifkan `code .`, di VS Code tekan:

```text

```

Lalu cari:

```text

```
