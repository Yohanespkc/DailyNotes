# **1. DIAGRAM: Struktur PCard sebagai Polynomial Functor**

Struktur dasar PCard adalah:

> **PCard = Σᵢ (MCardᵢ → PCardᵢ) × Πⱼ (PCardⱼ)**  
> (bentuk umum polynomial functor)

Berikut diagram visualnya—sesuai implementasi UI/JSON PKC:

```
                         ┌────────────────────────┐
                         │        PCard            │
                         │ (Polynomial Functor)    │
                         └───────────┬─────────────┘
                                     │
         ┌───────────────────────────┼───────────────────────────┐
         ▼                           ▼                           ▼
  Σ-Component                  Π-Component               Execution Events
 (Sum Type)                    (Product Type)                  (MCard)
 (Choice / branching)          (Composition)              (hash-only reference)
         │                           │                           │
         ▼                           ▼                           ▼
 ┌────────────┐              ┌──────────────┐             ┌───────────────┐
 │ Branch A   │              │   Child 1    │             │ Event MCard#1  │
 │ (hash-ref) │              └──────────────┘             ├───────────────┤
 ├────────────┤              ┌──────────────┐             │ Event MCard#2  │
 │ Branch B   │              │   Child 2    │             ├───────────────┤
 │ (hash-ref) │              └──────────────┘             │ Event MCard#3  │
 └────────────┘
```

Interpretasi:

- **Σ (Sum)** mewakili *struktur pilihan* (misal: konsep mana yang aktif → addition, multiplication, etc).  
- **Π (Product)** mewakili *komposisi sub-PCard* (relasi antar konsep, dependency graph).  
- **Event MCards** mewakili rekaman proses belajar (hash-only), bukan konten.

Setiap node PCard:
- Tidak memiliki teks bebas.  
- Hanya berisi referensi hash (MCard, Event).  
- Menghasilkan struktur komposisional PKC.

## 4. Spesifikasi: “Building PCards from Sacred Octagon Events”

Ini semacam **mini-standar resmi** antara tim game, tim PKC, dan tim AI (TOBA-LM).

---

### 4.1. Tujuan

Mendefinisikan pipeline yang:

1. Mengubah **event Sacred Octagon** → **Execution Event MCard**  
2. Mengubah kumpulan event + MCard konsep → **PCard** (polynomial functor)  
3. Menjamin:  
   - integritas hash  
   - pemisahan konten & struktur  
   - kompatibilitas dengan CLM & vector representation  

---

### 4.2. Input & Output

**Input (dari Sacred Octagon):**

- File JSON event mentah, misalnya:

```json
{
  "timestamp": "2025-02-10T10:12:00Z",
```

- `mcards/events/event_*.json`  
- `pcards/pcard_*.json`  
- `vectors/vec_*.json` (opsional, bila embedding dibuat)

### 4.3. Langkah-Langkah Pipeline

#### Langkah 1 – Normalisasi Event → Execution Event MCard

1. Sacred Octagon menulis JSON mentah ke buffer.  
2. Modul `event_normalizer`:
   - menambahkan metadata (schema_version, source, device info bila perlu)  
   - menghitung `event_hash = HASH(json_normalized)`  
   - menyimpan sebagai:

```json
{
  "mcard_type": "execution_event",
  "event_hash": "event_2025-02-10T10-12Z_f912ab",
  "schema_version": "1.0",
  "payload": {
    "timestamp": "2025-02-10T10:12:00Z",
    "player_id": "SO-USER-00123",
    "session_id": "SO-2025-02-10-1012",
    "level": 6,
    "score": 1240,
    "total_questions": 40,
    "correct": 36,
    "wrong": 4,
    "avg_time_per_question": 2.1,
    "concept_tags": ["addition_2digit", "placevalue_basic"],
    "error_patterns": ["carry_over_misplacement"]
  }
}
```

3. Disimpan ke:  
   `mcards/events/event_2025-02-10T10-12Z_f912ab.json`

Modul `concept_aggregator`:

- Mengelompokkan event berdasarkan `concept_tags`.  
- Contoh: semua event yang memuat `"addition_2digit"` dikumpulkan.

Output internal:

```json
{
  "concept_label": "addition_2digit",
  "aggregated_events": [
    "event_2025-02-10T10-12Z_f912ab",
    "event_2025-02-11T09-30Z_883cd1"
  ]
}
```


Jika sudah ada, cukup di-*update* bagian `related_events`.

#### Langkah 4 – Pembuatan PCard (Recursive Polynomial Case)

Modul `pcard_builder` (TOBA-LM side):

1. Mengambil:
   - MCard konsep target (mis. `mcard_add2digit_7af1c29d`)

   - Event hashes terkait  

2. Membuat struktur polynomial functor seperti contoh:

```json

  "pcard_hash": "pcard_add2digit_87ac12f9",

      "label": "addition_2digit",
      "mcard_hash": "mcard_add2digit_7af1c29d"
    }
  },
  "product": {
    "dependencies": [
      { "role": "prerequisite", "pcard_hash": "pcard_add1digit_f3aa128c" },
      { "role": "structural_support", "pcard_hash": "pcard_placevalue_basic_aa31ff02" }
    ]
  },
  "execution_events": [
    { "event_hash": "event_2025-02-10T10-12Z_f912ab" },
    { "event_hash": "event_2025-02-11T09-30Z_883cd1" }
  ],
  "vector_embedding": {
    "embedding_hash": "vec_pcard_addition2digit_ba11d2c4",
    "dim": 64
  },
  "created_by": "TOBA-LM",
  "timestamp": "2025-02-11T10:01:00Z"
}
```

3. File disimpan ke:  
   `pcards/pcard_add2digit_87ac12f9.json`

---

#### Langkah 5 – Embedding Vektor (Opsional tapi powerful)

Modul `vectorizer`:

- Mengambil hash-hash event & MCard & relasi PCard  
- Menghasilkan embedding vektor (`embedding_hash`) untuk PCard / MCard.

```json
{
  "vector_type": "pcard_embedding",
  "embedding_hash": "vec_pcard_addition2digit_ba11d2c4",
  "pcard_hash": "pcard_add2digit_87ac12f9",
  "dim": 64,
  "values_ref": "blob://vec_store/ba11d2c4"  // pointer ke storage biner
}
```

Embedding ini kemudian dipakai untuk:

- clustering  
- similarity search  
- geometri pengetahuan di Dashboard Nasional.

1. **Tidak ada PCard atau MCard yang menyimpan konten teks bebas dari user.**

3. Semua transformasi tercatat sebagai event hash.
