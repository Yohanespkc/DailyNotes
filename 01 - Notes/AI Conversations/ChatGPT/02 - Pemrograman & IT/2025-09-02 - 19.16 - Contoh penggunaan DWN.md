## 1. Skenario untuk **WhatsApp versi DWN**
### Masalah di sistem sekarang:
- Chat disimpan di server WhatsApp pusat (Meta).  
- Jika server down, pesan tidak bisa terkirim.  
- Data pengguna ada di server pihak ketiga (berisiko privasi).

### Solusi dengan DWN:
- Setiap pengguna punya **DWN pribadi** (bisa di ponsel, laptop, atau server kecil).  
- Pesan langsung disimpan di DWN penerima, bukan di server pusat.  
- Sinkronisasi antar perangkat dilakukan P2P (peer-to-peer) melalui DWN.  

### Alurnya:
1. A ingin kirim pesan ke B.  
2. A menulis pesan terenkripsi ke DWN milik B (alamat DWN B diketahui lewat DID/identitas terdesentralisasi).  
3. B membuka aplikasi WhatsApp-DWN → langsung ambil pesan dari DWN miliknya.  
4. Tidak ada server pusat, data tetap privat di DWN masing-masing.  

🔑 Keuntungan:  
- Privasi lebih baik (tidak ada pihak ketiga simpan chat).  
- Bisa kirim pesan meskipun WhatsApp “pusat” mati.  
- Data terenkripsi dan dimiliki pengguna.

---

## 2. Skenario untuk **Aplikasi Kesehatan (misalnya rekam medis digital)**
### Masalah di sistem sekarang:
- Rekam medis pasien tersebar di banyak rumah sakit → susah diakses.  
- Data sensitif biasanya tersimpan di server pusat (rawan bocor).  
- Pasien tidak benar-benar “memiliki” data kesehatannya.

### Solusi dengan DWN:
- Setiap pasien punya **DWN kesehatan pribadi** (di cloud pribadi atau server yang ia pilih).  
- Semua rekam medis (hasil lab, resep, riwayat operasi) disimpan di DWN ini.  
- Rumah sakit/dokter hanya dapat **akses sementara** lewat izin kriptografi.

### Alurnya:
1. Pasien datang ke RS baru.  
2. RS minta akses ke rekam medis → pasien memberi izin via DID.  
3. RS membaca data dari DWN pasien (misalnya hasil lab lama, riwayat obat).  
4. Setelah perawatan, RS menambahkan data baru (hasil tes terbaru) ke DWN pasien.  
5. Pasien bisa berbagi riwayat medis ke dokter lain kapan saja tanpa duplikasi data.

🔑 Keuntungan:  
- Pasien punya kendali penuh atas datanya.  
- Tidak perlu bawa berkas kertas atau copy hasil lab.  
- Mengurangi resiko kebocoran data karena hanya ada 1 sumber: DWN pribadi pasien.

---

👉 Intinya, **DWN memindahkan pusat data dari server perusahaan → ke pengguna langsung**.  
Jadi data (chat, rekam medis, file) ada di tangan pengguna, bukan di tangan perusahaan.
