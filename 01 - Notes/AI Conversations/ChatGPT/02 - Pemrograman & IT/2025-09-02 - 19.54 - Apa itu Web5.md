### 🤖 ChatGPT:
Web5 adalah konsep **decentralized web** yang dikembangkan oleh tim **TBD (anak perusahaan Block, milik Jack Dorsey)**.  

Singkatnya, Web5 mencoba menggabungkan elemen dari **Web2** (aplikasi modern yang interaktif) dan **Web3** (blockchain, desentralisasi, identitas mandiri), untuk menciptakan sebuah web baru yang lebih sederhana tetapi sangat **terpusat pada user**.  

### Inti dari Web5
1. **Self-Sovereign Identity (SSI)**  
   - Pengguna punya identitas digital yang benar-benar mereka kendalikan, bukan dikontrol platform (seperti Google, Facebook, atau Apple ID).  
   - Identitas ini bisa digunakan di berbagai aplikasi tanpa harus daftar ulang.

2. **Decentralized Web Nodes (DWNs)**  
   - Seperti “server pribadi” yang menyimpan data pengguna.  
   - Data bisa diakses aplikasi mana pun yang mendapat izin, tapi kendali penuh ada di tangan pengguna.

3. **Verifiable Credentials**  
   - Semacam sertifikat digital yang bisa diverifikasi tanpa bergantung pada otoritas pusat (misalnya ijazah digital, sertifikat kerja, dsb).

### Perbedaan dengan Web3
- **Web3**: banyak bertumpu pada blockchain & token ekonomi (cryptocurrency, NFT, smart contract).  
- **Web5**: lebih fokus ke **identitas & data pribadi**, blockchain hanya dipakai secukupnya (misalnya untuk identitas terdesentralisasi), tidak mengharuskan token/crypto di setiap aplikasi.

### Contoh Skenario
Bayangkan kamu punya akun musik.  
- Di Web2: playlist-mu tersimpan di Spotify, kalau pindah ke Apple Music harus bikin ulang.  
- Di Web5: playlist itu tersimpan di **DWN pribadimu**, dan bisa diakses aplikasi musik apa pun, karena datanya milikmu, bukan milik platform.

---

### 1. **Self-Sovereign**  
👉 *Users maintain complete control over their data and digital identity*  
- Artinya: identitas dan data **bukan lagi disimpan & dikuasai platform** (misalnya Google, Facebook, atau Apple).  
- Pengguna menyimpan semuanya di DWN miliknya (bisa di perangkat pribadi atau server kecil).  
- Setiap aplikasi hanya boleh mengakses data **jika pengguna memberikan izin**.  

📌 Contoh: Kamu punya DWN berisi data kesehatan. Saat konsultasi ke rumah sakit A, kamu kasih akses **sementara** hanya ke data rekam medis yang diperlukan. Setelah selesai, akses bisa kamu cabut.  

---

### 2. **Interoperable**  
👉 *Designed to work across different platforms and protocols*  
- DWN dibuat agar **aplikasi berbeda bisa mengakses data yang sama** dengan izin pengguna.  
- Tidak ada “lock-in” ke satu platform.  

📌 Contoh: Playlist musik kamu tersimpan di DWN. Spotify, Apple Music, dan YouTube Music semua bisa membaca playlist yang sama tanpa kamu harus ekspor-impor manual.  

---

### 3. **Resilient**  
👉 *Distributed architecture ensures high availability and fault tolerance*  
- DWN bisa disebar (distributed) di beberapa node, sehingga **tidak ada single point of failure**.  
- Kalau satu server mati, data tetap bisa diakses dari node lain.  

📌 Contoh: Dokumen pentingmu tersimpan di DWN yang direplikasi di laptop, server pribadi, dan cloud. Kalau salah satu rusak, datanya tetap aman.  

---

### 4. **Extensible**  
👉 *Supports various applications and services through standardized interfaces*  
- DWN punya antarmuka standar (API/protokol) yang bisa dipakai oleh aplikasi apa saja.  
- Artinya DWN bisa **tumbuh & diperluas**: dari aplikasi chat, media sosial, marketplace, hingga aplikasi kesehatan.  

📌 Contoh: DWN yang sama bisa dipakai untuk login ke aplikasi pendidikan, menyimpan ijazah digital, atau untuk WhatsApp offline—semua dengan satu identitas yang sama.  

---

⚡ Jadi ringkasnya:  
DWN adalah **“server pribadi” user** → identitas + data ada di tanganmu, bukan di platform. Aplikasi hanya *numpang akses*, tidak punya datanya.

### 1. **Token dalam Blockchain & Crypto**
- Token = representasi **nilai digital** yang dibuat di atas blockchain.  
- Bisa berupa **aset** (misalnya stablecoin, NFT, atau poin reward) atau **hak akses** tertentu.  
- Tidak selalu punya blockchain sendiri, biasanya ditumpangkan di jaringan lain (misalnya token ERC-20 di Ethereum).  

📌 Contoh:  
- **USDT (Tether)** → token stablecoin di Ethereum.  
- **Axie Infinity Shards (AXS)** → token game.  
- **NFT** → token unik untuk gambar, musik, atau item digital.  

---

### 2. **Token dalam Keamanan Digital (Auth Token)**
- Token = **kode digital sementara** yang dipakai untuk otentikasi atau mengakses layanan.  
- Biasanya dipakai agar pengguna tidak perlu login ulang dengan username/password setiap kali.  

📌 Contoh:  
- Saat kamu login ke aplikasi, server kasih “access token” → setiap request berikutnya cukup bawa token itu.  
- Token bisa berupa **JWT (JSON Web Token)**, digunakan di banyak aplikasi modern.  

---

### 3. **Token dalam Bahasa & AI (Natural Language Processing)**
- Token = unit dasar teks yang dipakai model AI/LLM untuk diproses.  
- Bisa berupa **kata, potongan kata, atau bahkan huruf** tergantung model.  

📌 Contoh:  
Kalimat “Saya makan nasi” → bisa jadi 3 token (“Saya”, “makan”, “nasi”) atau lebih kecil lagi (“Sa”, “ya”, dst).  

---

### 🔑 Ringkasnya:
- **Crypto** → token = aset digital.  
- **Keamanan** → token = kunci akses sementara.  
- **AI/NLP** → token = potongan teks yang diproses mesin.

# 4) Quick-start: DWN lokal dengan `dwn-sdk-js`
**Instalasi**
```bash
mkdir my-dwn && cd my-dwn
npm init -y
npm i @tbd54566975/dwn-sdk-js
```
**Contoh minimal (ESM)**
```js
// index.mjs
import { Dwn, DataStream, RecordsWrite, Jws, TestDataGenerator } from '@tbd54566975/dwn-sdk-js';
import { DataStoreLevel, EventLogLevel, MessageStoreLevel } from '@tbd54566975/dwn-sdk-js/stores';

const messageStore = new MessageStoreLevel();
const dataStore = new DataStoreLevel();
const eventLog = new EventLogLevel();
const dwn = await Dwn.create({ messageStore, dataStore, eventLog });   // buat DWN

const alice = await TestDataGenerator.generateDidKeyPersona();         // DID: did:key (dev)
const data = new TextEncoder().encode('Hello DWN');

const write = await RecordsWrite.create({
  data, dataFormat: 'application/json', published: true,
  schema: 'https://example.com/schemas/demo',
  signer: Jws.createSigner(alice)
});

const result = await dwn.processMessage(alice.did, write.message, { dataStream: DataStream.fromBytes(data) });
console.log(result.status); // seharusnya 202 (accepted)

await dwn.close();
```
> Pola ini sesuai contoh resmi di README `dwn-sdk-js` (Level stores, RecordsWrite, JWS signer). citeturn1view0

# 5) Membuatnya “berjaringan”
Agar DWN bisa diakses pihak lain:
1) **Publikasikan endpoint DWN** di **DID Document** sebagai *service endpoint*. (Klien menemukan node Anda via DID.) citeturn2view0  
2) **Ekspos HTTP handler** (mis. Express) yang menerima & meneruskan **Messages** (Records/Protocols/Permissions) ke instance DWN. (Spesifikasi mendefinisikan struktur pesan & otorisasi via JWS.) citeturn2view0  
3) **Sinkronisasi multi-node**: jalankan beberapa instance (laptop, server desa, cloud) untuk replikasi keadaan pemilik DID yang sama. citeturn2view0

# 6) Menetapkan “aturan main” data (Protocols & Permissions)
- **Protocols** = “kontrak” struktur & aturan data (schema, format, ukuran, peran/role seperti *owner/viewer/writer*).  
- **Permissions** = izin CRUD & query berdasarkan peran/aktor.  
- Implementasikan dengan pesan **`ProtocolsConfigure`**, **`PermissionsGrant`**, dsb. (lihat contoh protokol & peran di spesifikasi). citeturn2view0

# 7) Enkripsi & privasi
- DWN mendukung **enkripsi per-pesan**; kunci simetris per record dibagi ke penerima via kriptografi kunci publik (mis. X25519 + AES-GCM). Aktifkan lewat properti `$encryption` di definisi protokol. citeturn2view0

# 8) Alternatif SDK “lebih lengkap” (DIDs/VCs/DWN)
Butuh paket terpisah untuk DID, kredensial, agen identitas, dsb? Lihat monorepo **`web5-js`** (`@web5/api`, `@web5/dids`, `@web5/credentials`, dll.). citeturn3view0

# 9) Checklist produksi (singkat)
- **Metode DID**:  
  - *Dev*: `did:key` (tanpa infrastruktur).  
  - *Prod*: `did:web` (mudah dioperasikan) atau `did:ion` (anchoring Bitcoin, lebih tahan sensor). citeturn0search18turn0search6

## 3) Buat file minimal: `index.mjs`
Salin kode ini:

```js
// index.mjs
import { Web5 } from '@web5/api';

async function main() {
  // 1) Buat/ambil DID + koneksi ke DWN lokal
  const { web5, did } = await Web5.connect();
  console.log('DID saya:', did);

  // 2) Tulis satu record JSON ke DWN saya
  const note = { title: 'Catatan Pertama', body: 'Halo DWN 👋' };
  const { record } = await web5.dwn.records.create({
    data: note,
    message: {
      dataFormat: 'application/json',             // penting: format data
      schema: 'https://example.org/schemas/note'  // bebas, gunakan URL skema kamu
    },
  });
  console.log('Record dibuat dengan id:', record.id);

  // 3) Query semua catatan (berdasarkan schema)
  const { records } = await web5.dwn.records.query({
    message: {
      filter: { schema: 'https://example.org/schemas/note' }
    }
  });

  console.log('Jumlah record ditemukan:', records?.length ?? 0);
  for (const r of records ?? []) {
    const data = await r.data.json();            // helper: ambil payload sebagai JSON
    console.log('→', data);
  }
}

main().catch(console.error);
```

> API `Web5.connect()` memberi objek `web5` dan `did`, lalu kamu bisa `create/query/read/delete` record di DWN. `data` boleh teks/objek/file, asalkan `dataFormat` sesuai (mis. `application/json`). citeturn10view0

## 5) (Opsional) Mematikan sinkronisasi jarak jauh
Secara default, saat Tech Preview SDK bisa menyertakan endpoint DWN jarak jauh. Kamu bisa matikan **sync**:

```js
const { web5, did } = await Web5.connect({ sync: 'off' });
```

Atau **mengatur endpoint DWN** kamu sendiri:
```js
const { web5, did } = await Web5.connect({
  techPreview: { dwnEndpoints: ['https://dwn.domain-kamu.org/'] }
});
```
> Opsi `sync` & `dwnEndpoints` didukung SDK saat Tech Preview. citeturn10view0

---

## 6) (Opsional) Baca kembali satu record tertentu
Jika kamu menyimpan `record.id`, kamu bisa `read`:

```js
const { record: one } = await web5.dwn.records.read({
  message: { filter: { recordId: record.id } }
});
console.log('Isi record spesifik:', await one.data.json());
```
> `read()` menerima filter (paling umum `recordId`), juga bisa `protocol/contextId/protocolPath`. citeturn11view1

---

## 7) (Opsional) Membuat “aturan main” data pakai **Protocol**
Untuk interoperabilitas lintas aplikasi, DWN mendukung **Protocols** (struktur tipe data, peran, izin, batas ukuran, dsb.). Contoh definisi di spesifikasi: ada `types`, `dataFormats`, `structure`, dan aturan `$actions`. Kamu bisa konfigurasikan dengan `web5.dwn.protocols.configure(...)`. citeturn4view0

> Saran pemula: jalan dulu tanpa protocol. Setelah paham alur `create/query/read`, baru definisikan protocol agar data kamu konsisten & portable.

---

## 8) (Opsional) Tentang **DID**
DWN diikat ke **DID**. DID = pengenal terdesentralisasi yang punya **DID Document** (berisi kunci & service endpoints), dipakai untuk autentikasi/otorisasi dan penemuan endpoint (termasuk endpoint DWN). citeturn6view0

---

## 9) Troubleshooting cepat
- **Node ≤ 18**: butuh polyfill `globalThis.crypto` (lihat snippet di README `@web5/api`).  
- **Format data**: cocokkan `message.dataFormat` dengan data yang kamu kirim (mis. `text/plain`, `application/json`). citeturn10view0

## B.1) Pasang & buat contoh minimal
```bash
mkdir dwn-lowlevel && cd dwn-lowlevel
npm init -y
npm pkg set type=module
npm i @tbd54566975/dwn-sdk-js
```

Buat `demo.mjs`:
```js
import { Dwn, DataStream, RecordsWrite, Jws, TestDataGenerator } from '@tbd54566975/dwn-sdk-js';
import { DataStoreLevel, EventLogLevel, MessageStoreLevel } from '@tbd54566975/dwn-sdk-js/stores';

const messageStore = new MessageStoreLevel();
const dataStore = new DataStoreLevel();
const eventLog = new EventLogLevel();
const dwn = await Dwn.create({ messageStore, dataStore, eventLog });

const alice = await TestDataGenerator.generateDidKeyPersona();     // DID dev: did:key
const data = new TextEncoder().encode('Hello DWN (low-level)');

const write = await RecordsWrite.create({
  data,
  dataFormat: 'text/plain',
  published: true,
  schema: 'https://example.org/schemas/demo',
  signer: Jws.createSigner(alice)
});

const res = await dwn.processMessage(alice.did, write.message, { dataStream: DataStream.fromBytes(data) });
console.log(res.status); // { code: 202, ... } jika sukses

await dwn.close();
```

Jalankan:
```bash
node demo.mjs
```

> Contoh di atas mengikuti pola dari README `dwn-sdk-js` (LevelDB stores + `RecordsWrite` + JWS signer). Untuk browser/React Native ada catatan polyfill. citeturn3view0

import { Web5 } from '@web5/api';
import fs from 'node:fs';

const LAST_ID_FILE = '.lastId';

async function main() {
  const { web5 } = await Web5.connect();

  if (!fs.existsSync(LAST_ID_FILE)) {
    console.log(`File ${LAST_ID_FILE} tidak ditemukan. Jalankan dulu: npm run create`);
    process.exit(0);
  }

  const recordId = fs.readFileSync(LAST_ID_FILE, 'utf8').trim();
  if (!recordId) {
    console.log('Record ID kosong di .lastId');
    process.exit(0);
  }

  const { record } = await web5.dwn.records.read({
    message: { filter: { recordId } }
  });

  if (!record) {
    console.log('Record tidak ditemukan.');
    process.exit(0);
  }

  const data = await record.data.json();
  console.log('Record dibaca:', { id: record.id, ...data });
}

main().catch(err => {
  console.error('Error:', err);
  process.exit(1);
});
EOF

import { Web5 } from '@web5/api';
import fs from 'node:fs';
import path from 'node:path';
import url from 'node:url';

const __dirname = path.dirname(url.fileURLToPath(import.meta.url));
const protocolPath = path.resolve(__dirname, '../configs/protocols/notes.protocol.json');

async function main() {
  const { web5 } = await Web5.connect();

  if (!fs.existsSync(protocolPath)) {
    console.error('Protocol file tidak ditemukan:', protocolPath);
    process.exit(1);
  }
  const definition = JSON.parse(fs.readFileSync(protocolPath, 'utf8'));

  const result = await web5.dwn.protocols.configure({
    message: { definition }
  });

  console.log('Status konfigurasi protocol:', result?.status);
  console.log('Protocol ID:', result?.protocol?.protocol);
}

main().catch(err => {
  console.error('Error:', err);
  process.exit(1);
});
EOF
