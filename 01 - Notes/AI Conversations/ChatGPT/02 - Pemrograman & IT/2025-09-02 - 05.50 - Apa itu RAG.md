# 💬 Apa itu RAG

**Tanggal:** `2025-09-02 05.50`  
**Sumber:** ChatGPT Export  

---

### 👤 User:
apa itu RAG dan bagaimana cara kerjanya?

### 🤖 ChatGPT:
RAG adalah singkatan dari **Retrieval-Augmented Generation**, sebuah pendekatan dalam kecerdasan buatan (AI), khususnya pada **Large Language Models (LLM)**.  

🔎 **Ide utamanya:**  
Alih-alih hanya mengandalkan pengetahuan yang ada di dalam model (hasil training), RAG menggabungkan **retrieval** (pencarian informasi dari sumber eksternal, misalnya database, dokumen, atau knowledge base) dengan **generation** (kemampuan model bahasa untuk menyusun jawaban).  

---

### 🔧 Cara Kerja RAG
Secara sederhana ada dua tahap:

1. **Retrieval (Pencarian Informasi)**
   - Saat user mengajukan pertanyaan, query diubah menjadi representasi vektor (embedding).
   - Sistem mencari dokumen/teks yang paling relevan di dalam basis pengetahuan (misalnya: database perusahaan, kumpulan PDF, website, atau bahkan Wikipedia).
   - Hasil pencarian berupa potongan teks (passages/documents) yang relevan.

2. **Generation (Pembuatan Jawaban)**
   - LLM menerima *context tambahan* berupa potongan teks hasil retrieval.
   - Model kemudian menyusun jawaban dengan menggabungkan konteks eksternal + pengetahuan internalnya.
   - Hasilnya lebih akurat, terkini, dan sesuai domain.

---

### 🎯 Contoh
Misalkan ada chatbot perusahaan:
- **Tanpa RAG** → ditanya "Bagaimana cara klaim garansi produk A?" → model bisa salah jawab atau mengarang.
- **Dengan RAG** → sebelum menjawab, model mencari di database *manual garansi* → menemukan aturan → lalu menyusun jawaban yang sesuai.

---

### 🧩 Arsitektur RAG (umumnya)
- **User Query → Embed → Retriever → Document Store → Relevant Docs → Generator (LLM) → Final Answer**  
  Document Store bisa berupa:  
  - Vector database (Pinecone, Weaviate, Milvus, FAISS)  
  - Knowledge graph  
  - SQL/NoSQL database  

---

### ⚡️ Kelebihan RAG
- Memberikan **jawaban berbasis data terbaru** (tidak terbatas training model).  
- Mengurangi **halusinasi** (jawaban ngawur).  
- Bisa **dikustomisasi per domain** (misalnya hukum, medis, internal perusahaan).  
- Lebih hemat dibanding retraining model besar.  

### 🚧 Kekurangan
- Butuh **infrastruktur tambahan** (retriever, vector DB).  
- Kualitas jawaban sangat tergantung pada **kualitas data eksternal**.  
- Retrieval yang tidak tepat → jawaban tetap bisa salah.

## 🐳 **Docker**
- **Apa itu:** Docker adalah **platform containerization**, yaitu cara untuk membungkus aplikasi beserta semua dependensinya (library, config, runtime) ke dalam **container**.  
- **Tujuan:** Supaya aplikasi bisa dijalankan **dimana saja** (di laptop, server, cloud) tanpa masalah "kok di komputer saya jalan, tapi di server nggak?".  
- **Cara kerja:**
  1. Developer membuat **Docker Image** (cetakan aplikasi + dependensi).  
  2. Image dijalankan → jadi **Docker Container** (aplikasi yang sedang berjalan).  
  3. Container terisolasi tapi ringan (berbagi kernel dengan host OS, beda dengan Virtual Machine yang berat).  

👉 Bayangkan Docker seperti "kotak makanan": di dalamnya ada lauk + nasi lengkap, jadi mau dimakan di rumah atau di kantor, rasanya sama.

---

## ☸️ **Kubernetes (K8s)**
- **Apa itu:** Kubernetes adalah **sistem orkestrasi container**.  
- **Tujuan:** Mengelola banyak container dalam skala besar secara otomatis (scaling, load balancing, recovery, rolling update).  
- **Kenapa perlu:** Kalau aplikasi kecil, cukup 1–2 container (Docker saja cukup). Tapi kalau sudah ratusan/ribuan container di banyak server, perlu manajer → itulah Kubernetes.  
- **Cara kerja:**
  1. Kamu definisikan **manifest** (YAML/JSON) berisi: aplikasi apa, berapa jumlah replikanya, resource yang dibutuhkan.  
  2. Kubernetes scheduler menempatkan container di node (server) yang tersedia.  
  3. Kubernetes memastikan aplikasi selalu **running**. Kalau ada container crash → otomatis dibuat ulang.  
  4. Bisa scale up/down container sesuai kebutuhan.  

👉 Bayangkan Kubernetes seperti "manajer dapur restoran":  
- Docker = kotak makanan siap saji.  
- Kubernetes = manajer yang mengatur ribuan kotak makanan supaya dikirim tepat waktu, jumlahnya cukup, dan kalau ada kotak rusak langsung diganti.  

---

## 🔑 Ringkasnya
- **Docker** = bikin & jalankan container (unit aplikasi).  
- **Kubernetes** = atur & kelola banyak container secara otomatis di cluster server.
