## 2. Skema 1 PCard Matematis (format YAML)

Bayangkan ini isi 1 file PCard di PKC:

```yaml
id: PCard.Math.Add2NoCarry.v1
kind: PCard
version: 1
title: "Penjumlahan 2 Digit Tanpa Carry (GASING Level 1)"
description: >
  Menjumlahkan dua bilangan 2 digit tanpa proses carry.
  Hanya berlaku jika penjumlahan tiap digit (puluhan dan satuan) < 10.
  Dirancang untuk tahap awal pembelajaran penjumlahan GASING.

# 1. TANDA TANGAN FUNGSI (TYPE SIGNATURE)
signature:
  input:
    - name: a
      type: MCard.Num2Digit        # bilangan 2 digit: 10..99
    - name: b
      type: MCard.Num2Digit
  output:
    - name: c
      type: MCard.Num2Digit

# 2. STRUKTUR DATA MCard YANG DIHARAPKAN
mcard_schema:
  MCard.Num2Digit:
    fields:
      - name: tens
        type: Int
        constraints: "1 <= tens <= 9"
      - name: ones
        type: Int
        constraints: "0 <= ones <= 9"
    derived:
      value: "10 * tens + ones"

# 3. PRA-KONDISI (PRECONDITIONS)
preconditions:
  - name: "Digit-sum-without-carry"
    expression: |
      let (a_t, a_o) = (a.tens, a.ones)
      let (b_t, b_o) = (b.tens, b.ones)
      in (a_o + b_o < 10) && (a_t + b_t < 10)
    human_readable: >
      Penjumlahan digit satuan dan digit puluhan masing-masing harus < 10
      (tidak boleh terjadi carry).

# 4. DEFINISI FUNGSI (IMPLEMENTATION AS PURE FUNCTION)
definition:
  expression: |
    let (a_t, a_o) = (a.tens, a.ones)
    let (b_t, b_o) = (b.tens, b.ones)
    let c_o = a_o + b_o
    let c_t = a_t + b_t
    in MCard.Num2Digit { tens = c_t, ones = c_o }
  properties:
    - "Deterministik: input yang sama -> output yang sama"
    - "Tanpa efek samping, tidak mengubah MCard input"

# 5. PASCA-KONDISI (POSTCONDITIONS)
postconditions:
  - name: "Value-correctness"
    expression: |
      c.value == a.value + b.value
    human_readable: "Nilai bilangan hasil harus sama dengan penjumlahan nilai input."
  - name: "No-carry-preserved"
    expression: |
      (c.ones < 10) && (c.tens < 10)
    human_readable: "Hasil tetap 2 digit dan tidak memicu carry baru."

# 6. CONTOH-KASUS UJI (TEST VECTORS)
test_vectors:
  - name: "34 + 25 = 59"
    input:
      a: { tens: 3, ones: 4 }   # 34
      b: { tens: 2, ones: 5 }   # 25
    expected_output:
      c: { tens: 5, ones: 9 }   # 59
  - name: "41 + 36 = 77"
    input:
      a: { tens: 4, ones: 1 }   # 41
      b: { tens: 3, ones: 6 }   # 36
    expected_output:
      c: { tens: 7, ones: 7 }   # 77

# 7. KASUS YANG TIDAK DIIJINKAN (ILLEGAL STATE)
illegal_cases:
  - name: "Carry di satuan"
    example:
      a: { tens: 3, ones: 8 }   # 38
      b: { tens: 2, ones: 7 }   # 27
    reason: "8 + 7 = 15 >= 10 → melanggar precondition Digit-sum-without-carry"
    required_pcard: "PCard.Math.Add2WithCarry.v1"
  - name: "Carry di puluhan"
    example:
      a: { tens: 7, ones: 2 }   # 72
      b: { tens: 6, ones: 1 }   # 61
    reason: "7 + 6 = 13 >= 10 → melanggar precondition Digit-sum-without-carry"

# 8. KOMPOSISI (BAGAIMANA PCard INI DIGUNAKAN BERSAMA YANG LAIN)
composition:
  previous_stage:
    - "PCard.Math.NumRecognition2Digit.v1"      # siswa mengenali & menulis bilangan 2 digit
  next_stage:
    - "PCard.Math.Add2WithCarry.v1"             # penjumlahan dengan carry
    - "PCard.Math.AddSequenceNoCarry.v1"        # menjumlahkan 3–4 bilangan 2 digit tanpa carry
  can_be_lifted_to:
    - "PCard.Math.AddColumnNoCarry.v1"          # versi kolom vertikal (algoritma tulis tradisional)

# 9. KAITAN DENGAN VCard (NILAI / SERTIFIKASI)
```

## 3. Cara kerja PCard ini pada 1 contoh konkret

Misal input:

- `a = 34` → `MCard.Num2Digit { tens = 3, ones = 4 }`
- `b = 25` → `MCard.Num2Digit { tens = 2, ones = 5 }`

**Langkah PCard:**

1. **Cek tipe & schema**
   - Pastikan `a` dan `b` benar-benar `MCard.Num2Digit`.
2. **Cek preconditions**
   - `a.ones + b.ones = 4 + 5 = 9 < 10` ✅  
   - `a.tens + b.tens = 3 + 2 = 5 < 10` ✅  
   → state ini **legal** untuk PCard ini.
3. **Hitung definisi fungsi**
   - `c_ones = 4 + 5 = 9`
   - `c_tens = 3 + 2 = 5`
   - Hasil: `c = MCard.Num2Digit { tens = 5, ones = 9 }` (nilai 59)
4. **Cek postconditions**
   - `c.value == a.value + b.value` → `59 == 34 + 25` ✅
   - `c.ones < 10` dan `c.tens < 10` → `9 < 10`, `5 < 10` ✅
5. **Log & provenance**
   - Eksekusi ini sendiri bisa direkam sebagai MCard baru (log eksekusi) kalau mau.

# II. Objek Formal yang Kita Gunakan

## 1️⃣ Basis bilangan (desimal)

Tuliskan bilangan sebagai vektor digit:

\[
\begin{aligned}
A &= \sum_{i=0}^{n} a_i \cdot 10^i \\
B &= \sum_{j=0}^{m} b_j \cdot 10^j
\end{aligned}
\]

dengan:
- \( a_i, b_j \in \{0,\dots,9\} \)
- setiap digit adalah **MCard.IntDigit**

---

## 2️⃣ PCard atomik: Digit Multiplication LUT

Definisikan **PCard dasar**:

\[
\boxed{

}
\]

Domain terbatas:
\[
d_1, d_2 \in \{0,\ldots,9\}
\Rightarrow
\text{LUT}_{\times} \subset \mathbb{N}
\]

Lookup table GASING:
```
0×0=0 … 9×9=81
```

✅ Dievaluasi sekali  
✅ Dipakai selamanya

# III. Perkalian Sebagai Konvolusi Diskret

## 1️⃣ Definisi Konvolusi Diskret

Untuk dua urutan diskret \(a_i\) dan \(b_j\):

\[
(a * b)_k = \sum_{i+j=k} a_i b_j
\]

---

## 2️⃣ Aplikasi ke Bilangan Desimal

Substitusikan:

\[
A \cdot B
= \left(\sum_i a_i 10^i \right)
  \left(\sum_j b_j 10^j \right)
\]

Distribusi:

\[
= \sum_{i,j} (a_i b_j) 10^{i+j}
\]

Kelompokkan indeks \(k=i+j\):

\[
\boxed{
A \cdot B
= \sum_{k=0}^{n+m}
\left(
\sum_{i+j=k} a_i b_j
\right) 10^k
}
\]

👉 **Inilah konvolusi.**

3. **Normalisasi digit (carry)**

## 2. Energi per operasi (orde besaran)

Berdasarkan paper low-power digital design dan perbandingan umum CPU/GPU vs SRAM:

### FLOPs (32-bit floating point, advanced node)
- 32-bit **mul/add**: kira-kira di **puluhan pJ** per operasi (10⁻¹¹ J) di banyak prosesor aritmatika modern.
- MAC (mul+add) ≈ sedikit lebih besar.

### LUT-ops (8–16 bit, small SRAM/ROM + add)
- **SRAM/ROM read** kecil: bisa turun ke **beberapa pJ** atau bahkan sub-pJ kalau:
  - jarak wire pendek
  - tegangan diturunkan
  - ukuran tabel kecil (100–1k entry)
- **Integer add 8–16 bit**: juga beberapa pJ (jauh lebih murah daripada 32-bit float mul).

👉 **Rasio kasar** (untuk use-case kecil-angkat seperti digit×digit):
- FLOP mul 32-bit vs LUT-ops 8–16 bit:  
  ~**5–20× lebih boros energi** untuk FLOP, tergantung node, voltage, arsitektur.

Artinya:
- Untuk tugas yang bisa dipecah jadi LUT + add (model GASING),  
  **GASING-AI chip dapat hemat energi satu orde besaran** dibanding MAC-heavy GPU, *dengan asumsi data terlokalisasi*.

---

## 3. Latency per operasi

### FLOPs
- Pipeline dalam beberapa stage (4–10 tahap).
- Latency 3–10 cycles (walaupun throughput satu hasil/cycle).
- Untuk operasi kecil (digit-level), pipeline cost ini “overkill”.

### LUT-ops
- **ROM/SRAM read + add**:
  - Akses memory local → 1 cycle
  - Add → 1 cycle
- Bisa di-*pipeline* sehingga:
  - Effective latency: **1–2 cycles**
  - Throughput: 1 hasil/cycle (bahkan banyak hasil/cycle lewat paralelisme).

👉 Untuk kasus **digit×digit** ala GASING:
- FLOP 32-bit: beberapa stage pipeline + pemborosan kapabilitas.
- LUT-ops: 1 cycle read + 1 cycle add.
- Jika di desain benar, **latency per digit-op bisa lebih pendek atau setara, tapi dengan energi jauh lebih kecil.**

## 4. Perkalian panjang: FLOPs vs GASING-LUT

Misal kita mau menghitung **perkalian dua bilangan 4-digit**:

### Model FLOPs (float 32-bit / int32)
- Biasanya:
  - konversi ke representasi 32-bit
  - 1 operasi MUL 32-bit → 1 hasil (plus potensi normalisasi)
- Energi: ~puluhan pJ sekali tembak  
- Latency: beberapa cycles pipeline.

### Model GASING-LUT (digit basis-10, 4-digit × 4-digit)

1. Representasi:  
   - A = a₀ + 10a₁ + 10²a₂ + 10³a₃  
   - B = b₀ + 10b₁ + 10²b₂ + 10³b₃  
2. Kita butuh 16 kombinasi `aᵢ × bⱼ`, tiap satu:
   - 1 LUT read (digit×digit)
3. Lalu konvolusi (penjumlahan terstruktur):
   - beberapa operasi add + carry normalize.

**Energi total (sangat kasar):**

- FLOP:
  - 1 MUL 32-bit: misal 20 pJ (sekali)
- GASING-LUT:
  - 16 LUT read @ ~2 pJ + ~20 add @2 pJ  
  - ≈ (16×2) + (20×2) = 72 pJ

Sekilas tampak **lebih boros**… tapi:

1. Itu kalau dibandingkan dengan *operasi tunggal MUL 32-bit*.
2. Untuk banyak tugas AI/ML:
   - banyak data kecil → overhead representasi 32-bit besar.
3. Untuk **pendidikan / kalkulator anak / edge-AI**:
   - angka sering kecil, domain sempit → LUT-ops bisa di-*quantize* sangat rendah.
4. Kalau kita pakai **basis non-10** (mis: 2⁴ atau 2⁸) dan packing digit:
   - LUT-ops bisa di-*vectorize* → satu LUT-read melayani beberapa digit sekaligus.
   - Energy per “effective multiply” turun drastis.

Jadi perbandingan realistis:
- Untuk *single big multiply*: FLOP bisa unggul.
- Untuk **banyak operasi kecil, berulang, domain sempit** (digit, quantized activations, local kernels):
  → LUT-ops bisa **hemat energi total** dan *lebih mudah di-paralelkan masif*.

   - Banyak latihan matematika, banyak langkah kecil

4. **Kesesuaian kognitif**:

# II. PCARD – SACRED OCTAGON PENJUMLAHAN  
## *Hukum belajar: kapan boleh lanjut, kapan tidak*

> **PCard adalah aturan sah perubahan kemampuan.**

---

## 4. PCard Dasar: Penjumlahan Tanpa Menyentuh 10

### **PCard.SO.Add.Basic**

```yaml
id: PCard.SO.Add.Basic
type: PCard
domain: SacredOctagon.Addition
prerequisites:
  - MCard.Mat.Add.Pair10Mastery.accuracy_percent >= 90
  - MCard.SO.Add.Session.finger_usage == false
operation:
  description: "Penjumlahan dua bilangan satu digit dengan hasil ≤ 10"
  method:
    - octagon_position
    - direct_lookup
postconditions:
  - correct_answers_ratio >= 90%
  - response_time_avg_sec <= 2.0
on_fail:
  redirect_to:
    - PCard.SO.Add.Pair10Reinforcement
```

📌 **Jika pra-kondisi tidak terpenuhi → PCard TIDAK BOLEH JALAN**

---

## 5. PCard Strategis GASING: Melintasi 10 (Crossing 10)

### **PCard.SO.Add.Cross10**

```yaml
id: PCard.SO.Add.Cross10
type: PCard
domain: SacredOctagon.Addition
prerequisites:
  - MCard.Mat.Add.Pair10Mastery.learning_status == complete
operation:
  description: "Penjumlahan yang melewati 10 menggunakan pasangan 10"
  decomposition:
    - step1: "pisahkan ke pasangan 10"
    - step2: "sisa dijumlahkan"
  example:
    - "8 + 7 = (8 + 2) + 5"
postconditions:
  - error_pattern.crossing_10 == 0
  - avg_response_time_sec <= 2.0
illegal_states:
  - finger_counting
  - direct_guess_without_decomposition
```

📌 Ini **inti GASING Penjumlahan**

---

## 6. PCard Ketahanan Konsistensi (Stability Check)

### **PCard.SO.Add.Stability**

```yaml
id: PCard.SO.Add.Stability
type: PCard
domain: SacredOctagon.Addition
prerequisites:
  - last_3_sessions.correct_answers_ratio >= 90
operation:
  description: "Uji kestabilan tanpa bantuan"
evaluation:
  sessions_required: 3
  aids_allowed: false
postconditions:
  - response_time_variance low
  - zero_finger_usage
outcome:
  success:
    unlock_next:
      - PCard.SO.Add.2Digit
  retry:
    - PCard.SO.Add.Cross10
```

📌 Anak **boleh cepat**,  
📌 tapi **tidak boleh rapuh**

---

## 7. PCard Remedial (Tanpa Label Negatif)

### **PCard.SO.Add.Pair10Reinforcement**

```yaml
id: PCard.SO.Add.Pair10Reinforcement
type: PCard
domain: SacredOctagon.Addition
triggered_when:
  - repeated_cross10_errors >= 2
operation:
  description: "Penguatan pasangan 10 lewat Sacred Octagon visual"
method:
  - slow_round
  - guided_hint
exit_condition:
  - MCard.Mat.Add.Pair10Mastery.accuracy_percent >= 95
```

📌 Remedial = **kembali ke hukum**,  
bukan hukuman.

## 2. Cara baca graf untuk guru

Bayangkan dashboard guru seperti “peta jalur belajar”:

1. **MCard: Pair 10 Mastery**
   - Menunjukkan: apakah siswa sudah kuat di **pasangan 10**.
   - Status bisa:
     - ❌ Belum
     - ⚠️ Hampir
     - ✅ Sudah

2. **PCard.SO.Add.Basic** (Penjumlahan ≤ 10, belum lintas 10)
   - Hanya aktif kalau Pair 10 cukup kuat.
   - Dashboard bisa tampil:
     - Progress: berapa soal sudah benar
     - Kecepatan rata-rata
   - Jika banyak salah → garis merah ke **PCard.SO.Add.Pair10Reinforcement**.

3. **PCard.SO.Add.Cross10** (Penjumlahan lewat 10)
   - Menjamin anak **pakai strategi GASING**:
     - pecah jadi pasangan 10
     - tambah sisa
   - Guru bisa lihat:
     - Berapa banyak kesalahan *crossing 10*
     - Apakah anak masih menebak

4. **PCard.SO.Add.Stability**
   - Mengecek: ini sudah benar-benar **mantap** atau baru “beruntung”.
   - Syarat:
     - 3 sesi Sacred Octagon
     - Akurasi stabil ≥ 90%
     - Tanpa jari, tanpa bantuan
   - Kalau lolos → muncul sinyal: **“Siap 2 digit”** (PCard.SO.Add.2Digit).

5. **PCard.SO.Add.Pair10Reinforcement** (Penguatan)
   - Aktif otomatis kalau:
     - kesalahan *crossing 10* berulang
     - atau Pair 10 belum stabil
   - Guru tinggal memberi permainan penguatan:
     - ronde lebih pelan
     - bantuan visual
     - tidak ada tekanan nilai

## 3. Skema dashboard sederhana (untuk 1 siswa)

Misalnya tampilan tabel ringkas:

| Node | Nama | Status | Keterangan singkat |
|------|------|--------|--------------------|
| MCard | Pair 10 | ✅ | 95% akurat, 1.2 detik |
| PCard | Add.Basic | ✅ | 92% benar, 1.6 detik |
| PCard | Add.Cross10 | ⚠️ | Masih salah di 8+7, 9+6 |
| PCard | Add.Stability | ⏳ | Baru 1 dari 3 sesi stabil |
| PCard | Pair10Reinforcement | Aktif | Disarankan 1 sesi penguatan |

**Legenda status:**
- ✅ = lulus / mantap
- ⚠️ = bisa, tapi belum konsisten
- ⏳ = sedang diuji stabilitas
- ❌ = belum
- Aktif = PCard remedial sedang berjalan
