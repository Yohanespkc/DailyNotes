# Kenapa LUT desimal kalah di CPU umum
- **Granularitas**: CPU menambah satu register 64-bit sekali jalan (carry-lookahead/skip/fast carry). LUT desimal bekerja **per digit** (basis-10), sehingga Anda menjalankan **O(n digit)** *akses tabel + kontrol alur* alih-alih satu instruksi add 64-bit.  
- **Akses memori & branch**: lookup → L1 cache (≈4 siklus) + penanganan carry dan percabangan; branch mispredict bisa 10–15+ siklus.  
- **Basis-10 vs basis-2**: representasi desimal (BCD) historisnya selalu lebih lambat/besar daripada biner; bahkan instruksi “DAA” (decimal adjust) di x86 ditinggalkan karena tidak efisien.  
- **Vektorisasi**: walau bisa dicoba mengemas digit per-byte dan “mengoreksi” >9 dengan tabel, biayanya (shuffle/permute + mask) masih jarang mengalahkan satu ADD + beberapa instruksi bantu.

> **Kesimpulan praktis**: untuk CPU/GPU umum, gunakan penjumlahan biner standar. LUT desimal berguna untuk **pengajaran GASING**, verifikasi langkah demi langkah, atau **hardware khusus** (FPGA/ASIC) yang bisa mem-*parallel*-kan banyak digit sekaligus.

# Kapan LUT bisa unggul
- **Hardware khusus**: di FPGA, Anda bisa membuat **LUT (a,b,carry_in) → (digit, carry_out)** dan mem-*pipeline* banyak digit paralel. Dengan lebar tetap (mis. 8–12 digit) dan frekuensi tinggi, ini bisa kompetitif untuk beban kerja spesifik.
- **Kasus edukasi/UX**: LUT memudahkan pelacakan proses “cara manusia”— cocok untuk tutor interaktif GASING, bukan untuk performa puncak.

# Inti desain: Parallel Decimal Carry-Prefix (PDCP)
Untuk setiap pasangan digit \(a_i, b_i\) (LSB → MSB), hitung serentak:

1) **Jumlah lokal dan status generate/propagate**
- \(s_i = a_i + b_i\)  
- **Generate** \(g_i = 1\) bila \(s_i \ge 10\)  
- **Propagate** \(p_i = 1\) bila \(s_i = 9\)  
  (intuisi: kalau \(s_i=9\), carry-out = carry-in; kalau \(s_i\le 8\), carry mati; kalau \(s_i\ge 10\), carry hidup)

2) **Prefix carry (paralel, O(log n))**  
Gunakan jaringan prefix (Kogge-Stone/Brent-Kung) dengan operasi asosiatif:
- Kombinasi dua blok berurutan \((g_k,p_k)\) ⊕ \((g_j,p_j)\) = \((G, P)\) dengan  
  \(G = g_k \lor (p_k \land g_j)\), \(P = p_k \land p_j\).
- Hasil prefix memberi semua \(c_i\) (carry-in per digit) sekaligus:  
  \(c_{i+1} = g_i \lor (p_i \land c_i)\) dengan \(c_0\) dari input.

3) **Seleksi digit via LUT ganda (tanpa cabang)**  
Siapkan dua nilai per digit, dihitung paralel:
- \(d0_i = s_i \bmod 10\)  (untuk \(c_i=0\))
- \(d1_i = (s_i+1) \bmod 10\) (untuk \(c_i=1\))  
Lalu multiplex: \(d_i = \text{mux}(c_i, d0_i, d1_i)\).  
Semua digit selesai serentak setelah sinyal carry tersedia.

**Hasilnya:** latency ~ **log₂(n)** tahap prefix + 1 tahap seleksi; throughput tinggi jika dipipeline. Ini persis semangat video Anda: LUT per digit jalan **serentak**, carry dihitung **sekali** lewat jaringan prefix.

# Dibanding adder biner di CPU
- **Asimtotik sama (O(log n))**, tetapi **konstanta latensinya lebih besar** di desimal: logika digit (deteksi \(s=9\), koreksi \(\bmod 10\)) dan jaringan prefix cenderung lebih lebar daripada gerbang biner.  
- **CPU umum** sudah punya adder biner ultra-optimum + jalur carry cepat antar-bit; desain desimal tak memanfaatkan jalur itu → di **software** tetap kalah.  
- **FPGA/ASIC**: Anda bisa menanam PDCP di LUT fabric, *pipelining* per stage. Untuk lebar tetap (mis. 8–12 digit per siklus), performanya bisa **sangat kompetitif**, terutama bila beban kerjanya memang desimal (UI/edukasi, kalkulator BCD, akuntansi khusus, dsb.).

# Flowchart “versi paralel” (lebih efisien & efektif)
Ganti rantai “B:9, C:9, …” menjadi 3 blok besar yang berulang:

1) **BLok S (per-digit, paralel):**  
   Input: \(a_i,b_i\) → Output: \(s_i, g_i, p_i, d0_i, d1_i\).  
   (Ini bisa diimplementasikan tabel 200-entri untuk \((a,b,c_{in})\), atau 100-entri untuk \((a,b)\) guna dapatkan \(s_i\), lalu turunkan \(g,p,d0,d1\) tanpa cabang.)

2) **Blok PFX (prefix carry):**  
   Masukan: vektor \((g_i,p_i)\) + \(c_0\) → Keluaran: semua \(c_i\).  
   (Gambar sebagai jaringan bertingkat: level 1 gabung pasangan, level 2 gabung kuartet, dst.)

3) **Blok SEL (per-digit, paralel):**  
   Masukan: \((d0_i,d1_i,c_i)\) → Keluaran: \(d_i\).  
   (Jika \(c_{n}\) masih 1, tambahkan digit terdepan.)

Dengan arsitektur ini, **semua digit dihitung serentak**, hanya **carry** yang diselesaikan lewat satu jaringan log-depth — alurnya ringkas, mudah dipipeline, dan persis mendukung demonstrasi GASING.

- Untuk tiap digit \(i\): \(s_i=a_i+b_i\)

  \end{cases}\)
- **Prefix carry**: \((G,P)\oplus(G',P')=(G \lor (P \land G'),\; P\land P')\).  
  Setelah prefix: \(c_{i+1} = G_{0..i}\; \lor\; (P_{0..i} \land c_0)\).
- **Seleksi digit**: \(d_i = c_i ? d1_i : d0_i\).

### A) SystemVerilog (parameter BASE & N)
```systemverilog
// ============================================================
// GASING PDCP Adder — Generic Base-B, N digits (LSB = index 0)
// ============================================================
module pdcp_adder #(
  parameter int BASE = 10,
  parameter int N    = 8,
  localparam int W   = $clog2(BASE)
)(
  input  logic              cin,                // usually 1'b0
  input  logic [W-1:0]      A   [N],            // A[i] < BASE
  input  logic [W-1:0]      B   [N],            // B[i] < BASE
  output logic [W-1:0]      S   [N],            // result digits
  output logic              cout
);

  // ---------- Stage S: per-digit (paralel) ----------
  logic g   [N];
  logic p   [N];
  logic [W-1:0] d0 [N], d1 [N];

  for (genvar i=0; i<N; ++i) begin : GEN_S
    // s0 in [0 .. 2*(BASE-1)]
    logic [W:0] s0;  // one extra bit to hold >= BASE
    assign s0 = A[i] + B[i];

    assign g[i] = (s0 >= BASE);
    assign p[i] = (s0 == BASE-1);

    // d0 = s0 % BASE; for our range this equals s0 - (g?BASE:0)
    assign d0[i] = s0 - (g[i] ? BASE : 0);

    // d1 = (s0 + 1) % BASE; simplified per cases:
    assign d1[i] = g[i] ? (d0[i] + 1) : (p[i] ? '0 : (d0[i] + 1));
  end

  // ---------- Stage PFX: carry prefix (O(log N)) ----------
  // level 0 seeds
  logic G0 [N], P0 [N];
  for (genvar i=0; i<N; ++i) begin
    assign G0[i] = g[i];
    assign P0[i] = p[i];
  end

  // iterative-doubling prefix
  localparam int L = (N<=1) ? 1 : $clog2(N);
  logic GL [L:0][N];
  logic PL [L:0][N];

  // level 0
  for (genvar i=0; i<N; ++i) begin
    assign GL[0][i] = G0[i];
    assign PL[0][i] = P0[i];
  end

  // levels 1..L
  for (genvar l=0; l<L; ++l) begin : GEN_LEVEL
    localparam int SHIFT = (1<<l);
    for (genvar i=0; i<N; ++i) begin : GEN_NODE
      if (i >= SHIFT) begin
        assign GL[l+1][i] = GL[l][i] | (PL[l][i] & GL[l][i-SHIFT]);
        assign PL[l+1][i] = PL[l][i] &  PL[l][i-SHIFT];
      end else begin
        assign GL[l+1][i] = GL[l][i];
        assign PL[l+1][i] = PL[l][i];
      end
    end
  end

  // c[i+1] = G_group(0..i) | (P_group(0..i) & cin)
  logic c [N+1];
  assign c[0] = cin;
  for (genvar i=0; i<N; ++i) begin
    assign c[i+1] = GL[L][i] | (PL[L][i] & cin);
  end
  assign cout = c[N];

  // ---------- Stage SEL: per-digit (paralel) ----------
  for (genvar i=0; i<N; ++i) begin : GEN_SEL
    assign S[i] = c[i] ? d1[i] : d0[i];
  end
endmodule
```

> Catatan: `A[i], B[i]` **harus** bernilai `0 .. BASE-1`. Untuk BASE bukan pangkat-2, `W=$clog2(BASE)` cukup (digit tetap muat). Operator `%` tidak saya pakai (diganti bentuk komparator + pengurangan konstan) agar sintesis ringan.

### B) VHDL (generic BASE & N) — ringkas & synthesizable
```vhdl
-- ===========================================
-- GASING PDCP Adder — Generic Base-B, N digit
-- ===========================================
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity pdcp_adder is
  generic (
    BASE : positive := 10;
    N    : positive := 8
  );
  port (
    cin  : in  std_logic;
    A    : in  unsigned(ceil_log2(BASE)-1 downto 0)  vector (0 to N-1);
    B    : in  unsigned(ceil_log2(BASE)-1 downto 0)  vector (0 to N-1);
    S    : out unsigned(ceil_log2(BASE)-1 downto 0)  vector (0 to N-1);
    cout : out std_logic
  );
end entity;

architecture rtl of pdcp_adder is
  function ceil_log2(n : positive) return natural is
    variable v : natural := 0; variable x : natural := n-1;
  begin
    while x > 0 loop v := v + 1; x := x / 2; end loop;
    return v;
  end;

  constant W : natural := ceil_log2(BASE);

  type bool_vec is array (natural range <>) of std_logic;
  type uvec     is array (natural range <>) of unsigned(W-1 downto 0);

  signal g, p : bool_vec(0 to N-1);
  signal d0,d1: uvec(0 to N-1);
  signal c    : bool_vec(0 to N);
begin
  -- Stage S (parallel)
  gen_s: for i in 0 to N-1 generate
    variable s0 : unsigned(W downto 0);
  begin
    s0 := resize(A(i), W+1) + resize(B(i), W+1);

    g(i) <= '1' when to_integer(s0) >= BASE else '0';
    p(i) <= '1' when to_integer(s0) =  BASE-1 else '0';

    d0(i) <= std_logic_vector(s0 - ( (g(i)='1') ? to_unsigned(BASE, W+1) : (others=>'0') ))(W-1 downto 0);
    d1(i) <= (others=>'0') when (p(i)='1' and g(i)='0')
          else std_logic_vector( (s0 - ( (g(i)='1') ? to_unsigned(BASE, W+1) : (others=>'0') )) + 1 )(W-1 downto 0);
  end generate;

  -- Prefix (iterative doubling; log N levels)
  c(0) <= cin;
  -- Untuk ringkasnya, di VHDL Anda bisa implementasikan prefix
  -- dengan array 2D dan generate seperti versi SystemVerilog di atas.

  -- Seleksi
  gen_sel: for i in 0 to N-1 generate
    S(i) <= d1(i) when c(i)='1' else d0(i);
  end generate;
  cout <= c(N);
end architecture;
```
> NB: Bagian prefix bisa diisi persis seperti pola **iterative-doubling** pada SystemVerilog (gunakan array 2D `GL(l)(i)`/`PL(l)(i)`); saya ringkaskan agar jawaban tetap padat.

### C) Referensi software (C) — basis-B generik
```c
// GASING PDCP (software reference) — base-B generic
#include <stdint.h>
#include <stdlib.h>

// a[i], b[i] in [0, B-1], len = N, LSB at index 0
void pdcp_add_baseB(const uint8_t* a, const uint8_t* b, int N, int B,
                    uint8_t* s_out, uint8_t* cout, uint8_t cin) {
  // Stage S
  uint8_t *g = malloc(N), *p = malloc(N), *d0 = malloc(N), *d1 = malloc(N);
  for (int i=0; i<N; ++i) {
    int s0 = a[i] + b[i];
    g[i] = (s0 >= B);
    p[i] = (s0 == B-1);
    d0[i] = (uint8_t)(s0 - (g[i] ? B : 0));
    d1[i] = g[i] ? (uint8_t)(d0[i] + 1) : (p[i] ? 0 : (uint8_t)(d0[i] + 1));
  }
  // Prefix (linear here; in HW use parallel prefix)
  uint8_t c = cin;
  for (int i=0; i<N; ++i) {
    s_out[i] = c ? d1[i] : d0[i];
    c = (uint8_t)(g[i] || (p[i] && c));
  }
  *cout = c;
  free(g); free(p); free(d0); free(d1);
}
```

## Tips penting (untuk semua basis B)
- **Digit valid**: pastikan `0 ≤ a_i,b_i < B`, `cin ∈ {0,1}`.
- **LUT vs aritmetika**: untuk **B kecil** (≤16), LUT per-digit (B×B×2 entri) enak dan cepat; untuk **B besar**, gunakan bentuk komparator/sum seperti di atas agar tak meledak ukuran ROM.
- **Pipeline**: pecah menjadi 3 stage (S → PFX → SEL) untuk fmax tinggi.
- **Correctness check**: uji acak ribuan kasus dan bandingkan dengan aritmetika biasa di software (konversi ke basis-10 untuk verifikasi).
