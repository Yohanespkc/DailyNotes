### 🤖 ChatGPT:
Untuk mendapatkan **embedding vector dari ID token**, kamu perlu memahami bahwa:

- **Token ID** adalah bilangan bulat yang merepresentasikan kata/token tertentu dalam sebuah kamus (vocabulary).
- **Embedding vector** adalah representasi vektor dari token yang memiliki makna semantik dalam ruang berdimensi tinggi (misalnya 300 dimensi), dan biasanya digunakan sebagai input untuk model NLP seperti LSTM, Transformer, dsb.
- Proses mendapatkan embedding vector dari token ID umumnya dilakukan lewat **Embedding Layer**.

---

### 📌 Contoh Sederhana Menggunakan PyTorch

Mari kita pakai contoh sederhana dengan `torch.nn.Embedding`.

Misalnya kita punya:
- Vocabulary size: 10 kata
- Dimensi embedding: 4

```python
import torch
import torch.nn as nn

# Misal kita punya 10 token dalam vocab (ID 0 sampai 9)
vocab_size = 10
embedding_dim = 4

# Buat layer embedding
embedding = nn.Embedding(num_embeddings=vocab_size, embedding_dim=embedding_dim)

# Misalnya kita punya token ID 3
token_id = torch.tensor([3])  # Bisa juga beberapa: torch.tensor([1, 3, 5])

# Dapatkan embedding vector-nya
vector = embedding(token_id)

print(f"Token ID: {token_id}")
print(f"Embedding Vector:\n{vector}")
```

### 🧠 Apa yang terjadi?

- `nn.Embedding` menciptakan sebuah **lookup table** berukuran `(vocab_size x embedding_dim)`
- Ketika kamu berikan token ID, layer akan **mengambil baris ke-ID** sebagai embedding vector-nya

---


### 📈 Bagaimana nilai-nilai itu dihitung?

Nilai-nilai itu **tidak dihitung manual** — saat kamu menulis:

```python
embedding = nn.Embedding(num_embeddings=3, embedding_dim=4)
```

PyTorch otomatis menginisialisasi matriks `(3x4)` berisi angka acak, seperti ini:


- `embedding(torch.tensor([0]))` akan mengembalikan baris pertama `[a11, a12, a13, a14]`
- `embedding(torch.tensor([2]))` akan mengembalikan baris ketiga `[a31, a32, a33, a34]`

> Nantinya saat model dilatih, angka-angka di tabel embedding ini **diperbarui** agar makin bagus dalam merepresentasikan makna kata.

### 🎯 Tujuan Pelatihan

Kita ingin mengubah vektor embedding secara **bertahap melalui training** agar kata-kata yang mirip punya vektor yang dekat. Contoh:
- "saya" dan "aku" seharusnya punya vektor yang mirip.

### 👣 Langkah-Langkah Training Sederhana

Kita akan:
1. Punya kalimat contoh → `"saya makan nasi"`
2. Buat target → misalnya prediksi kata berikutnya
3. Gunakan **embedding + linear layer + loss function**
4. Latih model untuk memperbaiki embedding

### 🧪 Contoh Program Pelatihan Sederhana

```python
import torch
import torch.nn as nn
import torch.optim as optim

# Step 1: Vocabulary dan Token
vocab = {"saya": 0, "makan": 1, "nasi": 2}
inv_vocab = {v: k for k, v in vocab.items()}
vocab_size = len(vocab)
embedding_dim = 4

# Step 2: Data - kita mau prediksi kata berikutnya (next word prediction)
# "saya makan" -> "nasi"
inputs = torch.tensor([vocab["saya"], vocab["makan"]])      # [0, 1]
target = torch.tensor([vocab["nasi"]])                      # [2]

# Step 3: Model sederhana
class SimpleModel(nn.Module):
    def __init__(self, vocab_size, embedding_dim):
        super(SimpleModel, self).__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim)
        self.linear = nn.Linear(embedding_dim * 2, vocab_size)  # prediksi ke seluruh vocab

    def forward(self, x):
        embeds = self.embedding(x)            # (2, 4)
        flat = embeds.view(1, -1)             # (1, 8)
        out = self.linear(flat)               # (1, vocab_size)
        return out

model = SimpleModel(vocab_size, embedding_dim)

# Step 4: Loss dan optimizer
loss_fn = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=0.1)

# Step 5: Training
for epoch in range(50):
    model.zero_grad()
    output = model(inputs)
    loss = loss_fn(output, target)
    loss.backward()
    optimizer.step()

    if epoch % 10 == 0:
        print(f"Epoch {epoch}, Loss: {loss.item():.4f}")

# Step 6: Lihat embedding yang sudah dilatih
print("\nEmbedding setelah training:")
for idx in range(vocab_size):
    word = inv_vocab[idx]
    vec = model.embedding(torch.tensor(idx))
    print(f"{word}: {vec.detach().numpy()}")
```

---

### 💡 Penjelasan:

- Model kita punya 2 bagian:
  1. `nn.Embedding` → mengubah ID token menjadi vektor
  2. `nn.Linear` → prediksi kata berikutnya
- Loss function-nya `CrossEntropyLoss` untuk klasifikasi
- Optimizer-nya pakai `SGD` agar simpel
- Target: model belajar bahwa `"saya makan"` seharusnya diikuti `"nasi"`

## 📏 Konsep: **Cosine Similarity**

Cosine similarity mengukur **seberapa mirip arah dua vektor** di ruang berdimensi tinggi.

### Rumus:
\[
\text{cosine\_similarity}(A, B) = \frac{A \cdot B}{\|A\| \times \|B\|}
\]

Nilainya antara:
- **1** → sangat mirip (arah sama)
- **0** → tidak berkaitan (tegak lurus)
- **-1** → sangat berlawanan

---

## 🧪 Contoh Kode Sederhana


## 🔍 Fungsi `cari_kata_mirip`

```python
def cari_kata_mirip(kata_target, embedding_dict, top_n=3):
    if kata_target not in embedding_dict:
        print(f"Kata '{kata_target}' tidak ditemukan dalam embedding.")
        return []

    target_vec = embedding_dict[kata_target].reshape(1, -1)
    hasil = []

    for kata_lain, vec in embedding_dict.items():
        if kata_lain == kata_target:
            continue
        sim = cosine_similarity(target_vec, vec.reshape(1, -1))[0][0]
        hasil.append((kata_lain, sim))

    # Urutkan berdasarkan skor similarity tertinggi
    hasil.sort(key=lambda x: x[1], reverse=True)
    return hasil[:top_n]
```

## 🎯 Kasus: 27 + 29
Dalam biner:
- `27` = `011011`
- `29` = `011101`
  
Jumlahnya adalah `56` → `111000` (6-bit)

Jadi kita ingin menjumlahkan **dua bilangan 6-bit**.

---

## 1. ⚡ Ripple Carry Adder (RPA)

**Cara kerja**:
- Bit paling kanan dijumlahkan dulu
- **Carry-nya diteruskan satu per satu ke bit berikutnya**
- Proses serial → makin lambat kalau bit makin banyak

### ⏱ Estimasi Waktu:
Misal satu full adder butuh waktu `t_FA` (delay per bit), maka total delay:

\[
T_{RPA} = n \cdot t_{FA}
\]

Untuk `n = 6`:
- Misalnya `t_FA = 100ps` (picosecond, tergantung teknologi CMOS), maka:

\[
T_{RPA} = 6 \times 100ps = 600ps
\]

### ✅ Waktu untuk RPA 6-bit:
⏳ **sekitar 600 ps (0.6 nanodetik)**

---

## 2. ⚡ Carry Lookahead Adder (CLA)

**Cara kerja**:
- Tidak tunggu carry lewat satu-satu
- Menggunakan logika **Generate (G)** dan **Propagate (P)** untuk menghitung carry **secara paralel**

### ⏱ Estimasi Waktu:
Delaynya logaritmik terhadap jumlah bit:

\[
T_{CLA} \approx t_{PG} + t_{carry\_logic} + t_{sum}
\]

Misalnya:
- `t_PG` = waktu hitung P dan G = 50 ps
- `t_carry_logic` = hitung carry pakai logika tree = 2-level logika × 50 ps = 100 ps
- `t_sum` = 50 ps

\[
T_{CLA} = 50 + 100 + 50 = 200 ps
\]

### ✅ Waktu untuk CLA 6-bit:
⏳ **sekitar 200 ps (0.2 nanodetik)**

---

## ✨ Perbandingan Akhir

| Metode | Estimasi Waktu | Catatan |
|--------|----------------|---------|
| RPA    | ~600 ps        | Lambat karena serial carry |
| CLA    | ~200 ps        | Lebih cepat karena paralel |

> **Untuk penjumlahan 27 + 29, CLA bisa lebih cepat ~3× dari RPA** pada teknologi yang sama.

## ⚙️ Anggap-Anggapan Waktu Delay:

- ⏱ `t_FA` = waktu satu full adder (untuk RPA) = **100 ps**
- ⏱ `t_PG` = waktu hitung P dan G per bit = **50 ps**
- ⏱ `t_CL` = waktu carry lookahead logic = **log2(n) × 50 ps**
- ⏱ `t_SUM` = waktu hitung sum dari carry dan input = **50 ps**

## 🧪 Simulasi Python

```python
import math

def simulate_rpa(bits, t_fa_ps=100):
    delay = bits * t_fa_ps
    return delay

def simulate_cla(bits, t_pg_ps=50, t_cl_level_ps=50, t_sum_ps=50):
    # Hitung waktu generate & propagate
    t_pg = t_pg_ps
    # Hitung waktu logika carry lookahead (log2(n) level)
    t_cl = math.ceil(math.log2(bits)) * t_cl_level_ps
    # Hitung waktu sum
    t_sum = t_sum_ps
    delay = t_pg + t_cl + t_sum
    return delay

# Contoh: 27 + 29 = penjumlahan 6-bit
n_bits = 6

delay_rpa = simulate_rpa(n_bits)
delay_cla = simulate_cla(n_bits)

print(f"Waktu estimasi Ripple Carry Adder (RPA) untuk {n_bits} bit: {delay_rpa} ps")
print(f"Waktu estimasi Carry Lookahead Adder (CLA) untuk {n_bits} bit: {delay_cla} ps")
```
