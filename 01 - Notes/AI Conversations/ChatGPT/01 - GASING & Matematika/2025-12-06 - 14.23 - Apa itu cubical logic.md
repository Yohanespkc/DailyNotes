# 🟦 Apa Itu *Cubical Logic Model*?

**Cubical Logic Model** adalah pendekatan modern dalam logika dan matematika yang berbasis pada **geometri kubus** untuk memodelkan *pembuktian*, *komputasi*, dan *hubungan antar-konsep*.  

Ia muncul dari dunia **Homotopy Type Theory (HoTT)** dan **Cubical Type Theory**, yang mencoba memvisualisasikan ide-ide logika *bukan sebagai simbol abstrak*, tetapi sebagai **ruang** yang memiliki titik, garis, permukaan, dan bahkan volume.

Bayangkan logika yang tidak lagi bekerja seperti tabel 2D, tetapi seperti **kubus 3D** yang bisa kamu putar, isi, sambung, deformasi, dan gabungkan.

---

# 🟥 Intuisi Dasar: Logika = Ruang Kubus yang Bisa Dideformasi

Dalam logika tradisional:

- sebuah **pernyataan** = benar atau salah  
- sebuah **bukti** = rangkaian langkah linear  
- sebuah **fungsi** = pemetaan input → output

Dalam **cubical logic model**, struktur ini diperluas:

- sebuah **pernyataan** menjadi **titik** dalam ruang  
- sebuah **bukti** menjadi **garis** (path) antara dua titik  
- sebuah **persamaan** antara dua bukti menjadi **persegi** (square)  
- struktur logika tingkat tinggi menjadi **kubus**, **hypercube**, dst.

Dengan kata lain:  
> **Logika tidak lagi hanya simbol. Ia adalah geometri.**

---

# 🟧 Mengapa Disebut *Cubical*?

Karena model ini memakai **interval [0,1]** sebagai “dimensi logika”, lalu membuat:

- 1 dimensi → garis  
- 2 dimensi → persegi  
- 3 dimensi → kubus  
- …dan seterusnya (hypercubes)

Setiap dimensi mewakili **cara dua hal bisa “terhubung” atau “setara”**.

# 🟦 1. Intuisi Sederhana:  
## **Monad = Kotak Pintar yang Menjaga Alur Operasi**

Bayangkan Anda punya **kotak** yang berisi suatu nilai.  
Nilai itu bisa berupa number, teks, kemungkinan, error, daftar, dll.

Tetapi **kotaknya bukan kotak biasa** —  
dia tahu **aturan** bagaimana menjalankan operasi di dalamnya.

> **Monad = nilai + konteks + cara menggabungkan operasi di dalam konteks itu.**

Contoh konteks:
- “list” (ada banyak kemungkinan)
- “maybe” (bisa gagal)
- “IO” (interaksi input-output)
- “state” (ada memori yang ikut berjalan)
- “probabilitas” (setiap langkah punya peluang)

---

# 🟦 2. Analogi GASING

Dalam GASING:

- langkah-langkah (path) harus **sejalan**, tidak boleh memecah aturan.
- ada “alur penyederhanaan” yang tetap menjaga **makna operasi**.

Monad melakukan hal yang sama:  
**dia menjaga agar setiap langkah tetap konsisten dengan konteksnya.**

Jika GASING punya:
- nilai → angka
- konteks → model penyederhanaan
- path → langkah operasi

maka monad = **mesin yang memastikan setiap langkah GASING tersambung benar**.

---

# 🟩 3. Contoh Sangat Mudah

## **Maybe Monad (bisa gagal)**  
Bayangkan operasi matematika di mana *bisa terjadi error*.

Tanpa monad:

```
x = sqrt(9)   => 3
y = sqrt(-4)  => ERROR
```

Dengan monad:

- semua nilai disimpan dalam kotak: `Just 3`, `Nothing`
- jika suatu langkah gagal → kotak berubah menjadi `Nothing`
- langkah berikutnya otomatis skip

Jadi kita tidak perlu nulis `if error` manual.

Monad mengalirkan operasi **secara aman**.

---

# 🟧 4. Contoh intuitif lain: **List Monad**

Jika ada 2 kemungkinan:
```
x = [1, 2]
y = [10, 20]
```

Dan Anda membuat semua kombinasi:

```
x + y = [11, 21, 12, 22]
```

Yang membuat kombinasi otomatis itu adalah **List Monad**.

---

# 🟥 5. Definisi Formal (Versi Singkat)

Monad terdiri dari:

1. **Tipe pembungkus**:  
   `M a` = nilai bertipe `a` tapi dengan konteks (list, mungkin, IO, state…)

2. **Unit / return**:  
   `a -> M a`  
   membungkus nilai ke dalam konteks.

3. **Bind (>>=)**:  
   `M a -> (a -> M b) -> M b`  
   menggabungkan dua operasi yang masing-masing punya konteks.

Yang paling penting adalah **bind**, karena:

- dia membuka nilai di dalam kotak,
- menjalankan operasi,
- memasukkan kembali hasilnya ke dalam kotak,
- sambil memastikan konteks dijaga.

---

# 🟪 6. Monad = Cara Mengontrol Efek Samping

Efek samping = hal yang bukan pure matematika, misalnya:

- input/output  
- state/variabel  
- probabilitas  
- error  
- non-deterministik  

Bahasa fungsional (Haskell, OCaml, Scala) memakai monad untuk:

> “mengendalikan efek samping dengan tetap menjaga *kemurnian matematika*.”

Ini membuat monad sangat penting dalam:

- semantik bahasa pemrograman

**Tujuan Yama:** membuat sistem lebih aman dengan membatasi interaksi antar-proses pada level kernel.

# 🟦 1. Apa itu Yama LSM?

**Yama** adalah modul keamanan kernel Linux (Linux Security Module).  
Tugas utamanya:

### **1️⃣ Membatasi ptrace**
`ptrace` adalah kemampuan untuk:

- debugging proses lain  
- membaca memori proses lain  
- melakukan injeksi kode  

Ini berbahaya jika sembarang container bisa melakukannya.

Yama memastikan **hanya proses yang sah** bisa melakukan itu.

### **2️⃣ Melindungi symlink dan hardlink**
Mencegah serangan seperti:

- race condition attack  
- mengganti file secara diam-diam  
- membaca file sensitif lewat symlink

### **3️⃣ Meningkatkan isolasi antar-proses**
Ini relevan untuk multi-tenant Kubernetes.

---

# 🟧 2. Bagaimana Yama bekerja dalam Kubernetes?

Secara default, banyak distribusi Kubernetes (Ubuntu, Debian, RHEL, GKE, AKS, EKS) **mengaktifkan Yama**.

Karena cluster Kubernetes menjalankan banyak container dari banyak tim, Yama:

- mencegah container A mengintip proses di container B  
- melarang container melakukan debugging ilegal  
- melindungi data host dari eksploitasi symlink  

**Kubernetes sangat bergantung pada isolasi proses**  
→ dan Yama memperkuat isolasi itu.

---

# 🟨 3. Level Restriksi Yama (ptrace_scope)

Anda bisa melihat status Yama di node dengan:

```bash
cat /proc/sys/kernel/yama/ptrace_scope
```

Nilainya:

| Nilai | Deskripsi |
|-------|-----------|
| **0** | Bebas — *tidak aman* |
| **1** | Default — proses hanya bisa trace child proses (paling umum) |
| **2** | Sangat ketat — hanya boleh trace dengan UID sama |
| **3** | Ptrace *sepenuhnya diblokir* kecuali jika dikecualikan oleh root |

Di Kubernetes biasanya **1 atau 2**.

---

# 🟥 4. Bagaimana Yama mempengaruhi container?

Jika aplikasi dalam pod mencoba melakukan:

- debugging  
- profiling agresif  
- membaca stack proses lain  
- menggunakan perf tool  
- hotpatching  

Yama bisa memblokirnya.

Pesan error yang muncul bisa seperti:

```
ptrace: Operation not permitted
```

atau  
```
Permission denied by Yama LSM
```

---

# 🟩 5. Yama vs PodSecurityPolicy / Security Standards

Kubernetes punya mekanisme seperti:

- **seccomp**
- **AppArmor**
- **SELinux**
- **PodSecurity standards (restricted/baseline/privileged)**

Yama adalah **tambahan**—bekerja langsung di kernel.

PodSecurity hanya mengatur *apa yang boleh diminta* oleh pod.

Yama mengatur *apa yang tetap tidak boleh dilakukan*, meskipun pod sudah diizinkan.

---

# 🟦 6. Kapan kita perlu men-disable Yama?

Jarang. Tetapi ada beberapa kasus:

### 🔹 1. Profiling aplikasi (perf, gdb, eBPF tertentu)  
Beberapa tool menolak berfungsi jika Yama membatasi ptrace.

### 🔹 2. Debugging container di cluster development  
Jika developer ingin melakukan:

```bash
gdb -p <pid>
```

Yama bisa menghalangi.

### 🔹 3. Aplikasi HPC atau AI tertentu  
Misalnya model parallel training yang membutuhkan shared process access.

Namun waning: **men-disable Yama mengurangi keamanan cluster.**

---

# 🟧 7. Cara mengubah konfigurasi Yama

Contoh memperlonggar:

```bash
echo 0 | sudo tee /proc/sys/kernel/yama/ptrace_scope
```

Contoh memperketat:

```bash
echo 3 | sudo tee /proc/sys/kernel/yama/ptrace_scope
```

Agar permanen:

```
/etc/sysctl.conf
kernel.yama.ptrace_scope = 2
```
