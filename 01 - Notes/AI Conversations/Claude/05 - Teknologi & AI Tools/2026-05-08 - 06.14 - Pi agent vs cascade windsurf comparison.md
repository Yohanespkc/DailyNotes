## Pola 2: HMAC untuk token yang stateless (mirip JWT)

Kalau Bapak tidak ingin menyimpan setiap token di database, hash bisa dipakai untuk menandatangani payload. Server cukup menyimpan satu secret key, lalu verifikasi token dengan menghitung ulang hash-nya.

```python
import hmac
import hashlib
import json
import base64

SECRET = b"kunci-rahasia-server"

def buat_token(payload: dict) -> str:
    body = base64.urlsafe_b64encode(json.dumps(payload).encode()).decode()
    signature = hmac.new(SECRET, body.encode(), hashlib.sha256).hexdigest()
    return f"{body}.{signature}"

def verifikasi_token(token: str) -> dict | None:
    body, signature = token.rsplit(".", 1)
    expected = hmac.new(SECRET, body.encode(), hashlib.sha256).hexdigest()
    if hmac.compare_digest(signature, expected):
        return json.loads(base64.urlsafe_b64decode(body))
    return None
```

Inilah inti cara kerja JWT (JSON Web Token): payload + signature berbasis HMAC-SHA256. User tidak bisa memodifikasi payload tanpa mengetahui secret, karena hash akan berubah dan verifikasi gagal. Cocok untuk autentikasi API yang harus stateless.

## Pola 3: Hash dari konten sebagai identifier (content addressing)

## Catatan penting

Ada beberapa hal yang sering keliru kalau memakai hash sebagai token:

Pertama, pilih fungsi hash yang tepat. SHA-256 atau SHA-3 untuk token dan identifier umum. Untuk password (bukan token), wajib pakai bcrypt, Argon2, atau scrypt karena lebih lambat secara sengaja agar tahan brute force. MD5 dan SHA-1 sudah pecah dan tidak boleh dipakai untuk keperluan keamanan.

Kedua, jangan hash data yang mudah ditebak lalu pakai hasilnya sebagai token. Hash dari "user_123" atau dari timestamp bukan token, karena bisa ditebak. Token harus berasal dari sumber acak yang aman seperti secrets di Python atau crypto.randomBytes di Node.js.

Ketiga, gunakan pembanding constant-time saat verifikasi. Pakai hmac.compare_digest, bukan operator ==, supaya tidak rentan terhadap timing attack.

Keempat, hash adalah satu arah. Sekali data di-hash, tidak bisa dikembalikan ke aslinya. Jadi kalau token perlu menyimpan data yang harus dibaca kembali (misal user ID), pakai pola HMAC (Pola 2), bukan hash murni.
